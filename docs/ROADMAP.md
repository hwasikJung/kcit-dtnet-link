> 목표: 이후 모든 기능의 토대인 (1) 프로젝트 골격, (2) API 스펙 데이터, (3) CORS/Mixed Content를 해결하는 프록시가 **실제로 동작함**을 증명한다. 이 Phase가 끝나면 "브라우저 → 자체 프록시 → 대상 API → JSON 응답 화면 표시"가 검증된다.

### T0.1 — Nuxt 4 프로젝트 스캐폴딩
- 내용: Nuxt 4 (Vue 3.5) 프로젝트 생성, Pinia·vee-validate·zod·lucide/@nuxt/icon 설치, 기본 디렉토리 구조(`pages/`, `components/`, `composables/`, `stores/`, `server/api/`) 정리.
- 우선순위: 필수 / 선행: 없음
- **완료 기준(verify):** `npm run dev` 기동 후 브라우저에서 기본 페이지 200 응답. `npm run build` 성공.

### T0.2 — shadcn-vue + Tailwind 4 셋업
- 내용: shadcn-nuxt + Tailwind CSS 4 설정, reka-ui(radix-vue) 연동, 샘플 컴포넌트(Button, Accordion, Dialog, Input) 1개씩 설치 검증.
- 우선순위: 필수 / 선행: T0.1
- **완료 기준:** 샘플 페이지에 shadcn Button/Accordion이 정상 렌더 + Tailwind 유틸 클래스 적용 확인.

### T0.3 — API 스펙 추출 & 정적 스냅샷 (**8.2-8**)
- 내용: `http://220.76.251.227:9930/api-docs/swagger-ui-init.js` 인라인 `swaggerDoc` 파싱 → 프로젝트 내 정적 JSON(예: `app/data/api-spec.json`)으로 스냅샷. 26개 엔드포인트 · 9개 태그 · 파라미터(필수/타입/path·query·body) · summary를 구조화. `(수정예정)`/`(삭제예정)` 접두 플래그를 파생 필드로 추출.
- **의사결정 필요(8.2-8):** (a) 빌드 시 자동 추출 스크립트 vs (b) 최초 1회 스냅샷 후 수동 관리. → **MVP는 (b) 스냅샷 + 재추출 스크립트 동봉** 권장(자동화는 Backlog).
- 우선순위: 필수 / 선행: T0.1
- **완료 기준:** 스냅샷 JSON에 엔드포인트 26개 전량 존재. 각 항목이 `{tag, method, path, summary, params[], statusFlag}` 스키마 충족(스크립트로 카운트·스키마 검증). 좌표변환(src/dst/x/y), TTA(POST/multipart), path 파라미터(`{mgmbldpk}`,`{pnu}`) 등 예외 케이스가 정확히 표현됨.

### T0.4 — Nitro 프록시 라우트 + Origin 화이트리스트 (**8.2-1**)
- 내용: `server/api/proxy/[...].ts` 구현 — 대상 Origin으로 GET/POST 포워딩. 대상 Origin은 **환경변수 고정 화이트리스트**(임의 URL 프록시 금지, SSRF 방지). query 파라미터·path 파라미터·multipart(TTA)·EUC-KR 응답 인코딩 중계 처리.
- **의사결정 필요(8.2-1):** 인증키 추후 추가 여부 → 프록시에서 헤더 주입 지점을 환경변수로 선(先)설계(값은 비워두더라도 자리 확보).
- 우선순위: 필수 / 선행: T0.1
- **완료 기준:** 화이트리스트 외 Origin 요청은 4xx로 거부(테스트로 확인). 정상 요청은 대상 응답 상태코드·바디를 그대로 전달. 서버 로그에 대상 URL 기록.

### T0.5 — 프록시 PoC (E2E 1건 검증) — **Phase 0 게이트**
- 내용: 임시 페이지에서 `input_addr` 입력 → `/sqiapi/addr/addr_clean` 을 프록시 경유 호출 → 응답 JSON을 화면에 raw 출력.
- 우선순위: 필수 / 선행: T0.3, T0.4
- **완료 기준(게이트):** 실제 주소 1건("서울특별시 강남구 ..." 등) 입력 시 2xx + JSON 응답이 브라우저에 표시됨. **CORS·Mixed Content 오류 콘솔에 없음.** 이 기준 통과 = Phase 0 완료.

## Phase 2 — 메뉴1: API 테스트 콘솔 (MVP · 최우선)

> 목표: PRD P0 핵심. "주소 입력 → 실행 → 결과 확인"을 비개발자가 학습 없이 3클릭 이내 수행. 선행: Phase 1 + **T0.3(스펙 데이터) 필수**.

### T2.1 — API 목록 / 그룹 / 검색 (F-1)
- 내용: 9개 태그로 그룹핑한 아코디언/그룹 리스트. 각 항목 1차 노출은 **한국어 summary**, 메서드/경로는 보조 소형 표기. 검색 박스로 키워드 필터("정제","좌표" 등).
- 우선순위: P0 / 선행: T0.3, T1.2, T1.4
- **완료 기준:** 26개 엔드포인트가 9개 그룹으로 표시. "정제" 검색 시 주소정제 계열만 필터. 항목 선택 시 파라미터 폼 영역과 연동(선택 상태 Pinia 관리).

### T2.2 — 폐기/변경 예정 배지 파싱 (F-1 / 8.2 확정사항)
- 내용: summary의 `(수정예정)`·`(삭제예정)` 접두 파싱 → 배지 렌더 + 본문 요약에서 접두 제거. tooltip "향후 변경/폐기 예정 API".
- 우선순위: P0 / 선행: T2.1, T1.4
- **완료 기준:** 해당 엔드포인트(건물매칭 일부 #19·#20, 에너지매칭 #21·#22)에 배지 노출, 본문 요약에는 접두 미표기. 숨기지 않고 목록에 존재.

### T2.3 — 동적 파라미터 폼 자동 생성 (F-2)
- 내용: 선택 API 스펙 기반 폼 동적 렌더. `input_addr`→텍스트+예시 placeholder / path(`{mgmbldpk}`,`{pnu}`)→개별 필드 / boolean(`isRemoveNextLine` 등)→토글 / 좌표변환(src/dst/x/y)→필드(가능하면 src/dst 드롭다운) / 필수값 vee-validate+zod 검증.
- 우선순위: P0 / 선행: T2.1
- **완료 기준:** 4개 유형(단일 input_addr / path param / boolean 옵션 6종 / 좌표 4필드) API를 각각 선택 시 올바른 폼이 생성됨. 필수 미입력 시 실행 버튼 비활성 + 안내 문구.

### T2.4 — 실행 / 로딩 / 소요시간 (F-3)
- 내용: "실행" 버튼 → 프록시 경유 호출. 스피너, 소요시간(ms) 측정·표시.
- 우선순위: P0 / 선행: T2.3, T0.4
- **완료 기준:** 실행 시 로딩 표시 → 응답 수신 후 소요 ms 노출. 연타/중복요청 방지(진행 중 비활성).

### T2.5 — 결과 표시: JSON 뷰어 + 상태/오류 (F-4)
- 내용: 응답 JSON을 T1.3 뷰어로 표시. HTTP 상태코드 + 성공/실패 배지. Raw 복사. 오류 시 친화적 메시지("요청에 실패했어요…") + 원문 오류 접이식. (옵션) 실제 URL/cURL 표기.
- 우선순위: P0 / 선행: T2.4, T1.3
- **완료 기준:** 2xx 응답 녹색 배지 + JSON 정상 렌더. 4xx/5xx 시 적색 배지 + 친화 메시지 + 원문 접이식. 복사 버튼으로 raw JSON 클립보드 복사.

### T2.6 — TTA CSV 업로드 특수 케이스 (**8.2-6**)
- 내용: TTA(`POST /tta_match`, multipart, EUC-KR CSV, 컬럼 `place_code,place_name,input_addr`) 전용 파일 업로드 컴포넌트를 파라미터 폼에서 처리. 인코딩·컬럼 안내 문구.
- **의사결정 필요(8.2-6):** 지원 범위 = 단순 업로드+결과 표시 수준 vs 그 이상. → MVP는 **단순 업로드+결과 JSON 표시** 권장.
- 우선순위: P1(메뉴1 내 후순위) / 선행: T2.3, T0.4
- **완료 기준:** CSV 파일 업로드 → 프록시가 multipart 중계 → 응답 표시. EUC-KR 안내 노출. (범위는 8.2-6 결정에 따름)

### T2.7 — (제안) 최근 호출 히스토리 (F-5, **8.2-7**)
- 내용: 세션 내 최근 호출(API·파라미터·결과) 리스트를 브라우저 로컬 저장. 재실행/비교.
- **의사결정 필요(8.2-7):** 채택 여부 및 저장 방식(로컬 vs 서버). 서버 저장 시 DB 필요(범위 밖). → **로컬 저장 한정 또는 Backlog** 권장.
- 우선순위: 선택 / 선행: T2.5
- **완료 기준(채택 시):** 호출 후 히스토리에 항목 추가, 클릭 시 파라미터 복원. 미채택 시 Backlog로 이관 표시.

### T2.8 — 메뉴1 반응형 · 접근성 마감
- 내용: 좌우 분할 → 태블릿 상하 스택. 키보드 조작·대비·로딩/오류 상태 명시(PRD 4장). 3클릭 이내 첫 호출 UX 점검.
- 우선순위: 필수 / 선행: T2.5
- **완료 기준:** 태블릿 폭에서 레이아웃 붕괴 없음. 키보드만으로 API 선택→입력→실행 가능. 첫 호출까지 클릭 수 ≤ 3 확인.

> **Phase 2 게이트(메뉴1 MVP 완료):** 비개발자가 목록에서 API 선택 → 파라미터 입력 → 실행 → 결과 JSON 확인의 전체 흐름이 대표 API 4종(단일 addr / path param / boolean 옵션 / 좌표변환)에서 동작. 이 시점에 사용자 피드백 수집 → Phase 3 착수.

## Phase 3 — 메뉴2: 엑셀 기반 건물 정보 일괄 조회

> 목표: 엑셀 A열(`mgmBldPk`) 업로드 → 일괄 조회 → B열부터 결과 병합 → 웹 목록 → 행 클릭 Modal 상세.
> ⚠️ **설계 변경(2026-07-20 사용자 확정):** 데이터 소스를 PostgreSQL 직접 조회에서 **기존 프록시 경유 `GET /sqiapi/addr/mgm_bld_pk_info/{mgmbldpk}` API 호출**로 변경 → 8.2-2 블로커 해소. 아래 T3.0/T3.2의 DB 관련 세부 내용은 이 결정으로 대체됨(구현 내역은 상단 진행 현황 참고). 추가로 조회 이력을 브라우저 IndexedDB에 저장하고 이력 클릭 시 Modal로 재확인하는 기능(T3.7)이 신설됨.

### T3.0 — [블로커 해소] DB 연결 + 조회 대상 스키마 확정·실측 (**8.2-2, 8.2-4**)
- 내용: PostgreSQL 접속 정보(호스트/포트/DB명/계정 — **읽기 전용 계정 권장**) 확보 → `pg` 커넥션 풀을 Nitro plugin/유틸 싱글톤으로 셋업(`runtimeConfig` + 환경변수). 조회 대상 테이블/컬럼 스키마를 확정하고, 샘플 `mgmBldPk`로 **실제 조회 실측** → 표시 컬럼·순서·한글 컬럼명 매핑표(8.2-4) 초안 도출. 조회 쿼리는 **단일 모듈/설정으로 분리**(하드코딩 금지).
- 우선순위: **블로커(P3 최우선)** / 선행: T0.1
- **완료 기준:** (1) 서버 기동 시 DB 연결 성공(헬스체크 쿼리). (2) 샘플 mgmBldPk 3~5건 실측 조회 결과 확보(미존재 케이스 포함). (3) 컬럼(B열~) 매핑표 초안 문서화. **이 3가지 없이는 T3.2~T3.5 시작 금지.**

### T3.1 — 엑셀 업로드 & A열 파싱 (E-1, **8.2-3**)
- 내용: SheetJS로 xlsx(+필요 시 csv) 클라이언트 파싱. **A열=`mgmBldPk`**. 헤더 유무 자동 감지 또는 양식 안내. 업로드 즉시 A열을 테이블로 표시(호출 전). 유효성(빈값/중복/형식) 결과 표시.
- **의사결정 필요(8.2-3):** 1행 헤더 유무, A열 외 컬럼 허용, 템플릿 제공 여부.
- 우선순위: P1 / 선행: T3.0, T1.2
- **완료 기준:** 샘플 xlsx 업로드 시 A열 목록이 테이블에 렌더. 빈값/중복이 표시됨. (양식 규칙은 8.2-3 결정 반영)

### T3.2 — 일괄 DB 조회 route (E-2, **8.2-5**)
- 내용: `POST /api/bld/lookup`(가칭) — A열 목록을 받아 `WHERE mgm_bld_pk = ANY($1)` 배치 조회(청크 분할, **파라미터 바인딩 필수** — SQL 인젝션 방지). 진행률(청크 n/전체), 행별 상태(성공/**미존재**/실패) 반환. DB에 없는 PK는 미존재로 구분.
- **의사결정 필요(8.2-5):** 1회 처리 상한(예: 10,000행), 쿼리 청크 크기(예: 500건).
- 우선순위: P1 / 선행: T3.0, T3.1
- **완료 기준:** N행 업로드 시 진행률 갱신, 존재/미존재 행이 구분 표시. 임의 문자열 PK 입력에도 SQL 인젝션 불가(파라미터 바인딩 검증). DB 오류 시 친화적 오류 표시.

### T3.3 — 결과 컬럼 병합 (E-3, **8.2-4**)
- 내용: 조회 결과 컬럼을 T3.0 매핑표대로 B열부터 컬럼 추가(표시 컬럼 선정·한글 컬럼명).
- 우선순위: P1 / 선행: T3.0, T3.2
- **완료 기준:** 성공 행의 조회 컬럼이 B열~ 컬럼으로 병합. 매핑표와 컬럼 순서/이름 일치.

### T3.4 — 결과 목록 테이블 (E-4)
- 내용: A열+추가 컬럼 병합 목록을 테이블 렌더. 컬럼 다수 시 가로 스크롤+주요 컬럼 우선. 행 다수 시 페이지네이션/가상 스크롤.
- 우선순위: P1 / 선행: T3.3
- **완료 기준:** 병합 결과가 테이블로 표시. 넓은 컬럼 셋에서 가로 스크롤 동작, 대량 행에서 렌더 성능 저하 없음(페이지네이션/가상 스크롤).

### T3.5 — 행 클릭 → Modal 상세 (E-5)
- 내용: 행 클릭 시 Dialog로 해당 행 전체 정보 표시. 필드명/값 표 + 원본 JSON 접이식(T1.3 JSON 뷰어 재사용).
- 우선순위: P1 / 선행: T3.4, T1.3
- **완료 기준:** 행 클릭 시 Modal 오픈, 필드/값 표 + 원본 JSON 뷰어 표시. 닫기·키보드(ESC) 동작.

### T3.6 — (제안) 결과 엑셀 다운로드 (E-6, **8.2-5**)
- 내용: 병합 데이터(A열+B열~)를 SheetJS로 xlsx 생성·다운로드.
- **의사결정 필요(8.2-5):** 채택 여부.
- 우선순위: 선택 / 선행: T3.3
- **완료 기준(채택 시):** 다운로드한 xlsx가 화면 테이블과 동일 데이터/컬럼 순서. 미채택 시 Backlog 이관.

### T4.3 — 배포 구성 최종화 (**8.2-1**)
> **재정의(2026-07-21):** Nitro 프록시 제거(브라우저 직접 호출 전환) 및 메뉴2 DB 직접 조회 폐기로, 원래 내용(프록시 화이트리스트·DB 접속 정보 보안)은 **소멸**. 아래로 대체한다.
- 내용: `pnpm generate` 산출물 + `WEB-INF/web.xml`을 WAR로 패키징해 WAS(Tomcat 등)에 배포하는 구성 검증(docs/DEPLOY-WAR.md 절차). `NUXT_PUBLIC_API_BASE` 환경변수 재정의가 generate 산출물에 반영되는지 확인. HTTPS 서비스 시 Mixed Content 제약 안내 유지.
- **완료 기준:** (1) generate 산출물 기준 WAR 패키징 절차 재현 가능. (2) `NUXT_PUBLIC_API_BASE`를 바꿔 generate 하면 산출물에 해당 Origin이 구워짐을 확인. (3) WAS(또는 동등한 정적 서버 컨텍스트)에서 기동 스모크 — 메뉴1·2 페이지 로드 및 실호출 1건.
